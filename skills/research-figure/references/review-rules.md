# 图表审查规则

本文件是对 RSS《Best Practices for Data Visualisation》的中文选编与场景化改写；来源为 Andreas Krause、Nicola Rennie 与 Royal Statistical Society，按 CC BY 4.0 使用。不是全文翻译。具体章节、锁定版本和修改说明见 [sources.md](sources.md)。

## 判断顺序

先检查图能否准确回答研究问题，再检查可读性与风格。根据图形和输入选择相关规则，不为每张图机械填满检查表。

| 编号 | 要检查什么 | 采取什么行动 | 依据 |
|---|---|---|---|
| R01 | 读者、表达目的与比较对象是否明确 | 按趋势、比较、分布或关系选择图形；用图注说明窗口与样本 | RSS principles / audience、comparison |
| R02 | 轴范围或纵横比例是否改变比较印象 | 同量纲预测—真实值比较采用等范围、等比例；其他关系图按目的选择比例 | RSS principles / aspect ratios、axes |
| R03 | 柱长是否以真实零点为基线 | 柱图保留零点；若需要强调微小差异可换点图，明确范围 | RSS principles / origins and limits；这里收窄了上游一般性零点建议 |
| R04 | 多面板是否需要共享尺度 | 对同一物理量的直接比较优先共享轴；不同尺度合理时醒目标明 | RSS principles / layout、comparison |
| R05 | 连线是否暗示了不存在的顺序 | 时间序列按时间连接；无序类别使用点或柱，别以连线制造连续关系 | RSS principles / lines |
| R06 | 遮叠是否隐藏样本分布 | 选择透明度、点大小或密度表达；不能为视觉效果删数据 | RSS principles / points |
| R07 | 配色是否对应数据含义 | 分类、顺序、以中点发散的数据分别选合适调色方式；一致映射同一模型 | RSS styling / types of colour palette |
| R08 | 是否只靠颜色区分模型 | 结合线型、符号或直接标签；查看灰度与色觉差异下可辨性 | RSS styling / accessible colour palettes |
| R09 | 标注是否帮助解读且不遮挡数据 | 对关键点局部标注；必要时移到图注；避免逐点堆字 | RSS styling / annotations |
| R10 | 字体在最终使用尺寸是否可读 | 按论文/报告/幻灯片实际尺寸检查；少量字体与字号层级，检查中文和数学符号 | RSS styling / fonts |
| R11 | 装饰是否影响读数 | 删除无信息的 3D、阴影、网格或重复图例；保留有意义的基准线 | RSS principles / redundant elements、three-dimensional charts |
| R12 | 图外读者能否理解图的要点 | 图注/替代文字说明对象、单位、方向与关键现象；不写超出证据的结论 | RSS styling / alt text |

轴不应一律从零开始：例如时间序列或散点图可以使用有解释的局部范围，不能裁掉相关点且不说明。RSS 中一般印刷/网页与幻灯片的字号建议不能原样当作所有期刊图的硬性门槛；最终尺寸与用户给定投稿指南决定字号。顺序、共享轴、对数轴都要按实际数据判断。

## 本项目增加的数据与科研约束（不是上游逐字规则）

- D01：核对变量、单位、样本集合、时间窗、采样频率与预测时域。单位换算、聚合和筛选写入处理记录。
- D02：数据缺失应显式报告。时间序列保留缺口；散点比较说明有效样本及剔除规则。不要把空值画成零。
- D03：把原始值、汇总值和不确定性分开。误差线必须有定义（SD、SE、CI 或其他），CI 还需要置信水平及计算来源。脚本不会自动创造误差线或显著性。
- D04：代码改图保留已有统计计算；不能由“请美化”推导出修改指标定义、模型选择或测试集。
- D05：展示多个模型时保持模型与颜色/线型映射一致。是否“更好”取决于指标和应用目标，不能只凭曲线更平滑。
- D06：风格名称不等于期刊验收。只有核对用户提供或当次查证的目标期刊要求后，才能报告检查了哪些具体要求。

## 审查输出

按重要性报告可行动问题：`位置 → 观察证据 → 影响 → 建议 → 已验证/待验证`。可分为“影响科学解读”“影响阅读”“风格一致性”，不强行给总分。没有可行动问题时直说检查范围内未发现问题。

截图可以判断可见文字、布局、颜色和尺度标注；不能确认数据正确、统计显著、未裁剪样本或训练/测试泄漏。不要凭图推断这些事实。

脚本产生的 `render_log.json` 只是数据/渲染记录，不是科学评审结论。若无法查看导出图，明确写“已生成，尚未完成视觉检查”。
